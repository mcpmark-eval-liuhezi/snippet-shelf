# Contributing to Snippet Shelf

Thanks for wanting to help! Snippet Shelf is a tiny, opinionated home for reusable code snippets, and it stays tiny and opinionated because every change gets talked about before it lands.

## How to contribute

All changes to Snippet Shelf are proposed for review through pull requests — nothing is pushed straight to `main`. Here is how to propose a change:

1. **Check for an existing issue.** Look at the [issue tracker](https://github.com/mcpmark-eval-liuhezi/snippet-shelf/issues) — in particular the Snippet Shelf v0.1 roadmap — to see if the change is already planned. If it isn't, open a new issue describing what you want to change and why.
2. **Cut a branch.** Create a descriptive branch off the default branch (`main`), e.g. `docs/contributing`, `feature/search`, or `fix/snippet-sorting`.
3. **Make your change.** Keep it small and focused; one idea per pull request makes review much easier.
4. **Open a pull request.** Open the PR back into `main` from your branch. In the description, say what the PR does, why, and reference the issue it relates to (e.g. `Part of the snippet-shelf kickoff` with a link to the roadmap issue).
5. **Ask for review.** Once the pull request is open, mark it ready for review. A maintainer will look at it, and any changes that are requested should be pushed to the same branch so the PR picks them up automatically.
6. **Iterate until it's approved.** When review is finished and any automated checks pass, a maintainer merges the PR.

If you just want to discuss an idea before writing any code, commenting on the roadmap issue is a perfectly good way to start.
